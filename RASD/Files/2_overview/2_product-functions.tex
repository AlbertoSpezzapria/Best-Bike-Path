\subsection*{Sign-Up and Login}
\subsubsection*{Sign-Up}
The system lets the users register in order to manage and record data associated with each of them. When the user accesses the sign-up page for the first time, he’s offered the option to log-in with one of their existing accounts through an OAuth service. This way, his BBP account is linked to another account that he owns, making it easier to remember and access for him. 
The system also gives the user the possibility of entering his email and a new password and to create an account directly inside BBP. In that case, BBP checks that the password is complex enough and that no other account is associated with the same email. If the checks pass, the system stores the information in the DB and grants the user access to the platform.
\subsubsection*{Login}
If the user already has a BBP account or has previously linked their BBP account to one of the other existing accounts that he has through OAuth, the system grants them access the page. If the user access the page through OAuth, a button redirects them to the external account provider’s website, which handles the login process and sends the user back only when he completes the login procedure. If, on the other hand, the user registered directly on BBP, the system first checks whether an account associated with the provided email, and then verifies that the password matches. If thats the case the user is redirected to the website’s homepage.
\subsubsection*{Accessing BBP without accounts}
The user can also access BBP without logging in. In this case, the functionalities that are available are more limited. The system lets the user browse between public paths, but all the recording features and the private paths needs the login to work






\subsection*{Activity Recording}
The system allows registered users to record their cycling activities. When the user starts the recording, BBP continuously acquires real-time data from the mobile device, including:
\begin{itemize}
    \item GPS coordinates used to compute distance, average speed, and elevation;
    \item timestamps associated with all collected events;
    \item accelerometer and gyroscope data to detect irregularities on the road surface;
    \item potential stops inferred from speed variations.
\end{itemize}

During or after the trip, the system processes the collected data and generates a summary reporting distance, duration, average speed, and detected anomalies. If the user decides to save the activity, BBP stores it in the database and makes it available for personal statistics.

\subsection*{Automatic Path Creation}

When the user enables the automatic mode, BBP reconstructs the bike path followed during the activity. This includes:
\begin{itemize}
    \item continuous acquisition of GPS coordinates;
    \item segmentation of the route based on street structure and direction changes;
    \item detection of potholes, vibrations, or obstacles through accelerometer and gyroscope data;
    \item estimation of the user's speed to determine whether they are biking.
\end{itemize}

At the end of the activity, BBP generates a draft path containing:
\begin{itemize}
    \item a map of the complete route;
    \item a list of detected street segments;
    \item automatically identified road conditions and anomalies.
\end{itemize}

Since the automatically detected data may contain false positives, the user must review, confirm, or correct all generated information before it becomes publishable. After confirmation, the path and related annotations are stored and made available to the community.


\subsection*{Meteorological Data Integration}
When available, BBP enriches recorded activities with meteorological information obtained from an external weather service. After an activity is completed, the system sends:
\begin{itemize}
    \item the activity timestamps;
    \item the geographical coordinates of the route.
\end{itemize}

The external service returns weather conditions for the corresponding time and location, including:
\begin{itemize}
    \item temperature;
    \item general weather conditions (e.g., sunny, rainy, cloudy);
    \item wind speed and direction;
    \item possible weather alerts.
\end{itemize}

BBP associates the retrieved meteorological data with the recorded activity before storing it. These details are shown in the activity summary and are available for statistical analysis.










\subsection*{Manual Path Creation}
In addition to the automatic creation of bike paths, registered users can also create paths manually by directly entering the required data.
During this process, the platform asks the user to specify the name of the path, the streets that compose it, the condition of each segment, and the possible presence of obstacles or issues.
Once the information has been confirmed, the system stores the data in its database and allows the user to decide whether to make the path publishable, meaning visible to the entire community.
If the path is not made publishable, it remains visible only to the user who created it, within their personal profile.

\subsection*{Path Search from Origin to Destination}
Any user, including unregistered ones, can search for a bike path between two points using the search algorithm provided by the platform.
The system queries its database of publishable paths and identifies those that connect the specified origin and destination points.
The results are displayed on an interactive map and sorted in descending order based on a path score automatically computed by the platform.
The user can select one of the displayed paths to view detailed information, such as the total distance, estimated travel time, and overall path conditions.
\subsubsection*{Path Ranking}
The score assigned to each path is determined by considering several factors:
\begin{itemize}
    \item Path condition, where better-maintained paths receive higher scores;
    \item Freshness of information, favoring paths with more recent data;
    \item Path effectiveness, meaning how efficiently the path connects the two selected points.
\end{itemize}

\subsection*{Entering route condition information}
Each route, whether derived from an automatically recorded activity or manually created by the user, is characterized by a set of additional information describing its condition and rideability.
In particular, this information concerns:
\begin{itemize}
    \item{The condition of the roads that make up the route;}
    \item{The presence of obstacles, such as potholes, surface damage, or dangerous sections.}
\end{itemize}
Additional information is always managed through the same interface, but with different behavior depending on how the route was created:
\begin{itemize}
    \item{\textbf{Manual mode} During route creation, the user directly enters information about the condition of the roads and any obstacles.}
    \item{\textbf{Automatic mode} The system acquires data via the device’s sensors (GPS, accelerometer, gyroscope); therefore, the user finds this information already filled in. Each piece of information must be confirmed.}
\end{itemize}
Regardless of the mode, the user can always modify or update the additional information before and after publication, thus contributing to improving the quality of shared data.

\subsection*{Paths publication}
Registered users can choose to publish a route, making it visible and accessible to other users within the platform.
In particular, publication adds the route to \textit{BBP}’s public archive, making it available to all other users, including non-registered ones, through the route search and browsing functionality. Only published routes can be viewed by others and contribute to enhancing the quality of shared community data.
Publication always concerns the complete route, including all additional information such as road conditions and the presence of any obstacles.

\subsection*{Merging information from different users}
When multiple users provide information regarding the same route or overlapping sections, the BBP system automatically merges the received data concerning road conditions and the presence of obstacles. The merging process takes into account two main factors:
\begin{itemize}
    \item{The freshness of the information, meaning how recently it was provided;}
    \item {The number of confirmations received from different users for the same condition or status.}
\end{itemize}
In the case of conflicting reports, the system applies a weighted evaluation mechanism that prioritizes the most recent and most frequently confirmed information.
